# Поддержка видео-бота в maxapi-lite — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Дать ClipWizard возможность принимать видео до 250 МБ, скачивать его без передачи токена на CDN, загружать результат и отправлять сообщение после обработки вложения сервером MAX.

**Architecture:** Сохранить публичный `Bot` и клиент `MaxApiClient`. Клиент управляет авторизованной API-сессией и отдельной сессией передачи файлов без Authorization; потоковую передачу и восстановление скачивания вынести в небольшой `transfers.py`. Повторы отправки сообщения выполнять только после определённого ответа `attachment.not.ready` и только по явному флагу.

**Tech Stack:** Python >=3.9, aiohttp >=3.8, Pydantic >=2, pytest, pytest-asyncio, aiohttp.test_utils.

**Spec:** `docs/superpowers/specs/2026-10-15-video-bot-requirements.md` — точная копия предоставленного `maxapi-lite-tasks.md` из временного каталога.

## Global Constraints

- Целевое окружение из задания: `aiogram 3.4.1 → aiohttp 3.9.x`; библиотека при этом сохраняет `aiohttp>=3.8`, `pydantic>=2`, Python >=3.9.
- Новый API-домен по умолчанию: `https://platform-api2.max.ru`; доступен собственный `base_url`.
- Сохраняются существующие позиционные аргументы и возвращаемые словари. Новые настройки — keyword-only.
- TLS проверяется; сертификаты подключаются через SSLContext или переданный TCPConnector. При одновременной передаче обоих — ValueError.
- Авторизация только для API. Сессия для upload/download не получает токен бота, в том числе при редиректах.
- Никаких новых обязательных зависимостей на ffmpeg, Pillow, aiofiles или официальный maxapi.
- Утверждения о CDN, сроках URL, перекодировании и живом тесте взяты из задания; собственный тест с production-токеном в рамках составления плана не проводился.
- Каждый этап: сначала воспроизводящие тесты и их падение, затем реализация, успешная проверка, отдельный коммит. Публикация пакета — отдельное действие после проверки релиза.

## Review Focus

1. Обрыв скачивания и сервер, игнорирующий Range: результат должен совпадать с исходными байтами, без дублирования префикса — задача 6.
2. POST /messages завершился сетевым таймаутом: сообщение нельзя автоматически отправлять повторно, поскольку результат первого запроса неизвестен — задача 5.
3. Переданный извне connector: закрытие Bot не должно закрыть чужой ресурс; внутренние сессии и собственный connector закрываются — задача 1.
4. Не-JSON ответ загрузки video/audio с токеном из /uploads: допустимый успешный ответ не теряет токен; ответ HTTP >=400 не превращается в успешную загрузку — задача 4.
5. Отмена coroutine, истёкший CDN URL и несовпадающая длина: никакого успешного возврата с частичным файлом; существующий dest_path сохраняется — задача 6.

## Уточнения по текущему коду и выбранные решения

- `upload_file` уже передаёт открытый файл в `aiohttp.FormData`, не читая его целиком. Эту реализацию потоковой отправки сохранить и покрыть регрессией.
- `_media_mapping` не содержит `audio`: сейчас аудио попадает в `file`. Исправить вместе с токенами.
- `MaxApiError.code` сегодня означает числовой HTTP status. Сохранить это значение; строковый код MAX хранить отдельно в `api_code`.
- `send_callback` сегодня кладёт `callback_id` в JSON. План включает перенос в query по текущему контракту /answers и добавление `message`.
- Дефолтный HTTP total=300 с сам по себе не конфликтует с документированным polling timeout до 90 с. Нужна корректная обработка пользовательских коротких таймаутов и длительной передачи файлов.
- Лимиты «МБ/ГБ» в документации не уточняют байтовую систему. Для локальной проверки принять консервативные десятичные значения: image=50_000_000, video=250_000_000, audio=256_000_000, file=4_000_000_000 байт. Это решение явно указать в README.
- Проверка до запроса относится к размеру локального файла. Ограничения картинки 7680×7680, аудио 60 минут и поддерживаемые форматы описать в документации; проверку содержимого оставить серверу, без подключения декодеров.
- `wait_attachments=False` по умолчанию сохраняет немедленное поведение. Для видео-бота в примере включить `True`.
- HTTP 429 преобразовать в `RateLimited` с `retry_after`; автоматический повтор и общий ограничитель 30 rps в этот этап не входят.

## Отложенная возможность: resumable upload

Это отдельный исследовательский этап после обязательных задач. Документация описывает возможность, но её пример одновременно использует multipart, поэтому протокол нельзя угадывать. Сначала установить реальные методы, заголовки, идентификатор сессии и запрос offset на тестовом боте; затем отдельно спроектировать и протестировать восстановление после обрыва. До этого дефолт остаётся потоковым multipart. Докачка download из задачи 6 от этого исследования не зависит.
